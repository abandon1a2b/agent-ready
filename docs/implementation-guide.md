# 实现指导

[返回项目概览](../README.md)

本文提供接入规范的实现建议，帮助项目识别访问边界和常见风险。项目应根据部署方式、业务能力和已有基础设施选择方案，并验证实际效果。

## 1. 复用现有业务能力

建议在现有业务服务上增加 Agent 接入层，负责认证、参数解析和响应组织。业务权限、资源可见性、校验和配额应与原有入口一致。

不要直接将数据库操作包装为 Agent 接口，也不要依赖 Skill 中的文字限制替代服务端检查。调用者可以绕过 Skill 直接请求接口。

## 2. 本地服务

本地单用户软件可以采用仅本机访问的方式，通常将服务绑定到回环地址。绑定所有网卡后再依赖客户端声明“来自本机”，不能提供同样的访问边界。

需要明确：本机访问不等于识别了某个 Agent，其他本机进程也可能调用接口。接口实际具有的权限来自服务进程，尤其需要审视命令执行、文件读写和配置修改能力。

建议根据开放能力决定是否增加本地凭证，并检查来自浏览器的请求边界，例如 Host、Origin 和跨域策略。仅监听回环地址不应被理解为所有接口都自动安全。

如果允许远程访问，应重新评估认证和传输保护，不能直接沿用本地免认证假设。

## 3. 在线服务与 Token

多用户或远程服务建议使用绑定业务身份的访问凭证。Token 应有明确的用途、权限、有效期和撤销方式，避免把 Agent 接入等同于获得用户全部能力。

每次业务请求都应检查凭证是否有效，并结合当前用户状态、资源归属和业务权限判断操作是否允许。用户被禁用或权限变化后，已有凭证不能继续绕过这些限制。

建议通过认证请求头传递 Token，不放入查询参数、普通日志、文档或错误信息。无效凭证应明确报错，避免静默降级为匿名访问。

需要区分浏览器登录凭证与 Agent 访问凭证，明确它们分别可用于哪些接口。凭证管理和权限提升不应默认开放给 Agent 自行操作。

## 4. 浏览器授权

需要用户登录并同意授权时，建议复用应用已有的 OAuth / OIDC 基础设施，避免重新实现一套凭证签发服务。

建议采用以下流程：

1. Agent 从可信接入说明获取授权方式和地址，发起一次授权请求。
2. 用户在浏览器中登录，查看应用请求的权限并同意或拒绝。
3. 浏览器向已登记的回调地址返回一次性授权码。
4. Agent 校验回调属于本次授权，再通过授权码换取 Token。
5. Agent 确认当前身份和实际获得的权限，再调用业务接口。

回调 URL 不建议直接携带访问 Token。授权码交换、PKCE、回调匹配、状态校验以及 Token 验证应交给符合所选协议的成熟实现；OAuth 访问授权与 OIDC 身份确认的用途需要区分。

本地 Agent 的回调监听应限制在本机；远程 Agent 的本机回环地址不等于用户浏览器所在机器。无法接收回调的场景需要另外选择授权方式，不能简单放宽回调地址校验。

客户端登记方式、回调端口策略、续期及备用授权流程应由项目明确提供。实施时依据所采用协议及授权服务的实际契约验证，不让 Agent 猜测配置。

## 5. 权限与输入检查

权限检查应发生在服务端，并覆盖每一次资源读取和修改。知道资源 ID、持有有效 Token 或拥有某个操作权限，都不代表可以访问所有资源。

建议限制请求体、分页数量、上传大小及执行时间，并对参数类型、取值范围和路径进行校验。涉及命令和文件操作时，应明确允许的执行范围及运行身份。

业务内容、日志和外部链接属于数据，不应成为改变授权配置或执行任意操作的依据。凭证只能发送到其适用的可信服务，不能因业务内容中的链接而转发。

## 6. 写入与结果确认

建议为每个写入操作说明重复调用和请求超时后的行为。支持请求键去重时，由服务端保证约束；不支持时应明确提示先查询结果，避免自动重复提交。

异步操作应区分“已接受”和“已完成”，提供可查询的操作或资源引用。编辑操作需要考虑并发修改，避免无提示地覆盖较新的数据。

具体去重机制、状态模型和并发控制由业务决定，并在 Docs 中明确说明。

## 7. 工具分发

`/agent/download` 建议列出实际可用的工具及获取方式。CLI 通常需要区分操作系统和架构，SDK 通常需要区分语言和运行时版本，并说明与服务版本的兼容关系。

优先引用项目维护的可信发布渠道，避免根据用户内容动态选择下载源。直接分发文件时，建议提供完整性校验信息；安装说明应明确安装动作和所需权限。

工具内部同样应遵循服务的认证边界，避免内置共享秘密或输出真实凭证。暂无工具时明确说明，不提供无效下载链接。

脚本 CLI 可以通过 `curl <可信地址>/agent/cli.sh | sh` 即时执行业务命令，无需安装。应声明实际运行依赖、支持命令、参数、输出、退出码和版本，并作为可选工具通过 Manifest 与 Download 提供。脚本使用调用者的本机权限，不一定与服务进程权限相同；建议使用明确命令和经过校验的参数，避免将任意输入作为 Shell 代码执行。

## 8. 验证重点

实现后建议验证以下问题，而不仅检查接口能否成功调用：

- 本地服务是否只在预期地址可达，浏览器请求边界是否符合设计。
- 无效、过期、撤销的凭证，以及用户权限变化是否影响后续访问。
- 不同用户能否通过替换资源 ID 读取或修改他人资源。
- 授权拒绝、回调不匹配和授权码重复使用是否被正确处理。
- 请求超时、重复提交及并发修改是否产生意外副作用。
- 文档、日志和错误响应是否泄露凭证或内部敏感信息。
- 工具获取地址、平台选择和版本兼容说明是否与实际发布一致。

验证结果应记录在项目的实现记录中，并向开发者说明实际能力、效果及限制。
