一套面向 AI Agent 的应用接入规范，帮助 Agent 快速了解应用、发现能力，并选择直接调用接口、生成客户端或安装 CLI / SDK。

让 Agent 接入应用，应该有点像看菜单：知道能点什么、怎么点、是否需要先登录。最好别让它先钻进源码厨房。

## 设计原则

1. **统一接入方式，不统一业务实现。** 各项目使用相似的发现与描述方式，保留自己的业务接口和技术栈。
2. **以 `/agent/manifest` 为顶层接入目录。** 描述应用用途，以及 Skill、API 文档、CLI、SDK 和授权说明的位置，避免职责重复的概览入口。
3. **概览简短，详情按需读取。** Manifest 帮助 Agent 选择下一步，详细内容独立提供。
4. **以 Agent 理解和执行方便为准。** 说明性内容便于理解，生成客户端和自动安装所需的信息精确、可解析；内容格式根据用途选择。
5. **按实际能力声明接入资源。** 提供 Manifest、Skill、Docs 和 Download 四个基本入口；CLI、SDK 等工具资源按需提供，不要求项目提供全部使用方式。
6. **发现机制与权限模型分开。** 本地软件可以限制本机访问，在线服务可以要求授权 Token；不强制采用同一种认证，也不默认发现文档公开。
7. **描述与实际版本一致。** 文档、接口和接入工具应明确兼容关系，帮助 Agent 选择适用版本。
8. **用实际任务验证接入效果。** 以可完成的业务任务衡量交付，区分接口存在、调用成功与业务结果已确认。

## 基本入口

| 入口 | 职责 |
| --- | --- |
| `/agent/manifest` | 顶层接入目录：应用概况、接入资源及其位置、认证要求 |
| `/agent/skill` | 操作指南：使用方式、典型工作流和业务约束 |
| `/agent/docs` | 接口文档：参数、响应、错误、调用示例及精确契约的入口 |
| `/agent/download` | 工具获取目录：可用 CLI / SDK、兼容版本、安装方式及下载地址 |

四个入口均为规范的基本组成部分，路径不绑定具体内容格式。Manifest 引导 Agent 按需读取资源，不承载全部详细内容；Skill 聚焦操作流程，接口细节引用 Docs。已有文档可通过 Docs 入口组织和引用，避免重复维护。

简单说：Manifest 指路，Skill 带路，Docs 讲细节，Download 提供工具。各司其职，别让目录兼职百科全书。

Download 提供工具获取信息，可以链接到下载文件、包管理器或发布地址，不要求直接返回二进制文件。没有 CLI / SDK 的项目应明确说明暂无可用工具。

工具也可以是即时执行的脚本 CLI，例如通过 `curl <可信地址>/agent/cli.sh | sh` 调用业务能力，无需先安装 CLI。脚本 CLI 与二进制 CLI、SDK 并列，按需声明，不新增顶层入口。

这些入口用于接入说明，业务操作接口的位置由项目自行决定。入口的访问权限遵循应用的认证模型，不默认公开。

## 开始接入

1. 阅读 [实现指导](docs/implementation-guide.md)，确定本地访问、Token 或浏览器授权等适用方案。
2. 复制 [应用接入模板](templates/README.md)，填写四个入口及实际提供的工具，复用已有业务接口和文档。
3. 验证一个完整任务及关键失败路径，让接口描述与实际效果对得上。

模板使用 JSON Manifest 和 Markdown 说明，提供授权文档、可选脚本 CLI 及内部验证记录。字段可按应用需要调整；模板是填写起点，不是复制完就能自动营业的服务。

## 与 AI 一起实施

依据本项目实施的 AI 请阅读 [AI 实施协作约定](AGENTS.md)：开发前与开发者确认适用方案，开发后说明实际接口能力、验证效果和限制，并请开发者确认是否符合预期。

“接口已经写好”和“用户的事已经办好”，中间还差一次验证。
